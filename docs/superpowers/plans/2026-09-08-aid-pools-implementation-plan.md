# 幸存者协定援助资金池实施计划

状态：已确认规则的实施拆分；已接通四个计划的议会、报名、月度结算、退出、AI及年度复核；教育普及按用户最新要求默认开放，增长修正使用0.005作为实机对照起点。准入数值、引擎对照和人口效果仍待验证。最新规则以研究文档第十一至二十一节及用户后续指示为准，不能执行已被取代的双边合同方案。

## 1. 先验证引擎边界

- 离线核对已确认`country_innovation`调用封顶创新力计算，不直接用于用户要求的实际产出门槛；内置示例200不是本项目门槛。离线核对已支持从国家创新力加算/乘算修正重建未封顶产出，基础脚本与有限运算检查已写入；下一步与游戏实际值比对，再施加教育提供减益（产出−10%、上限−30点）检查资格反馈。引擎对照完成前不接入正式准入。
- 不能因GUI存在`GetWeeklyRawInnovation`就假定其能用于脚本数值。不临时移除修正来探测资格，也不将创新力上限替代实际产出。跨项目资格反馈需要可靠排除自身影响；无法排除时，提交明确的资格稳定替代方案再实施。
- `state_literacy_growth_add`用同存档同人口对照确认实际效果与单位，再确定数值。未验证前不将它作为已完成玩法对外发布。
- 预算费用/收入用同额样本确认实际财政变化，覆盖税收修正、借款和违约。每月只重算每周预算金额，不能重复做月度扣款。
- 核对`on_diplo_play_war_start`的root和战争状态就绪时点，并验证中途参战；加入外交博弈不等于开战。

## 2. 复用现有状态入口

| 现有入口 | 必要改动 |
|---|---|
| `ffpa_sc_begin_vote` / `ffpa_sc_resolve_vote` | 新援助议题通过后开启一个月报名，保留旧教育/贸易/工程议题含义 |
| `ffpa_sc_monthly` | 唯一全局时钟；先推进已有状态，再处理新开报名，避免创建当月立即扣掉一个月 |
| `ffpa_sc_stop_task` / `ffpa_sc_leave` | 统一撤销接受身份、费用与效果；保留五年启动间隔；重算受影响池 |
| `ffpa_sc_refresh` | 只根据权威状态同步修正，不把modifier当身份记录 |
| `ffpa_sc_ai_vote` / `ffpa_sc_ai_propose` / `ffpa_sc_ai_manage` | 加入提供方收益、接受方需求及全额费用判断；投票与报名独立 |
| 既有总览、按钮及本地化 | 增加报名、当前/全额周费、供给档位、提供国份额、剩余期限与退出原因 |
| 新战争子on_action | 只清理与同池提供国敌对的接受国；批量清理后按池统一结算 |

必须读取每个入口全部调用者再修改。新议题、任务和持久变量使用不与旧1/2/3含义冲突的标识。旧存档缺少新状态时视作未报名，不重置既有准备期、工程间隔或协议效果。

## 3. 数据与结算

固定分类：人才、教育、生产研究、社会研究、军事研究；各自汇总和分配，不创建双边合同矩阵。技术三个分类如何呈现提案菜单应保持玩家选择清楚，不改变按实际创新力准入的要求。

- 全局每池保存阶段、截止、有效人数与本期总额；国家保存本轮接受身份、锁定基础周报价、是否精简及原冷却。报名时不收费、不启动五年间隔。
- 状态为报名、执行、结束/失败；不保留战时暂停和和平恢复状态。36个月执行截止与60个月启动间隔从实际启动计。
- 同一份有效参与方快照先求人数/总额/威望，再线性分配；零威望均分。舍入余数需确定性处理，不能只验证无限精度算式。
- 人数档位0/1/2/3+对应0/50/75/100%；费用与收益同档位，精简再同时减半。基础报价锁定，实际周账单可因供给变化而变化。
- 无提供国或无报名接受国则失败；运行时任一方归零则结束。结束停止收入及服务减益；历史正常研究和人口结果不回滚。
- 接受国与同池任一提供国成为敌对方，退出整个该池，不仅扣除一份提供方收入。提供国继续服务其余接受国。和平不恢复，原截止和冷却不变。
- 教育提供减益固定产出−10%、上限−30点，每池一次；研究提供−5%类别速度、人才提供−10%资质仍是草案，不将后者悄悄标成独立批准值。

## 4. 可运行设计检查与交付验证

`python3 scripts/check_aid_pool_model.py`检查精确算术下的威望分账、供给档位、精简、角色互斥、启动失败、日期约束、战争退出及分池隔离。资金池部分是设计例子的可执行表达；创新力部分另直接读取本轮实际新增脚本检查运算。两者均不证明引擎结算、事件回调、AI或游戏性能；后续实际脚本须纳入现有`check_compact.py`的对应检查，避免长期只测试一份独立模型。

运行脚本接入后检查metadata、括号/顶层键、双语本地化键与BOM、`git diff --check`及原有检查。实机覆盖新档/旧档、2/3/10及较多成员、零供给/零需求、违约、战争及中途参战、保存读取、教育人口效果、税收叠加和月末财政。性能以同档同速度的有无项目对照为准，不以模型运行耗时冒充游戏性能。

已完成创新力基础数值和教育提供减益定义及相关静态检查。尚未完成引擎对照、具体准入数值校准、研究/人才提供代价定值及资金池活动运行脚本。不会因部分接口存在就把整个机制标为已实现；未经上述对照，不承诺识字率量级、即时战争回调覆盖或预算金额守恒。


## 6. 本轮核心落地状态

`ffpa_compact_aid_pools.txt`已实现参数化报名、实际启动、月度推进/结算、退出、结束与一年后单向精简。`check_aid_pool_scripts.py`直接读取这份脚本验证有限状态，原独立模型作为规则例子保留。实际类别参数、议会及AI入口、年度通知、战争回调和既有任务中止入口尚未接线；正式启用前必须一并完成，不能只加一个报名按钮。

分账中份额向下取到分，余数分给最高威望提供国；原生定点及预算守恒仍待验证。和平状态避免逐接受国检查提供国敌对，战时检查最坏情况仍有嵌套遍历，须在实机性能对照中覆盖。


## 7. 入口接通后的剩余验收

生产、社会、军事研究与人才培养已有实际调用入口。教育的技术接口、UI和修正定义保留，但显式禁用开放；只有识字率增长完成对照并加入效果后才启用。实际创新力200及GDP费率为公开标明的试运行参数，不能称作已获用户定值或完成开局校准。

新AI使用原生固定收支、储备与负债，研究需求按当前科研类别区分；一年后的事件选择每轮一次。旧官僚不足分支不直接清理援助。战争回调只刷新，不推进月份；是否覆盖所有参战路径仍需游戏验证。重点下一步：真实预算守恒、战争即时性、教育人口对照、旧档/GUI与AI长期运行。
